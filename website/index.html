为什么需要

AI Agent 有了读写你代码的权限，
谁在看着它的网络出口？

Claude Code、Cursor、Codex、MCP 后台服务……它们都能读你的仓库与 .env，而它们外发的每一个 HTTPS 请求对你完全不可见。现有的方案各缺一角：

🔌

LLM 网关管不住

LiteLLM / Helicone 等需要应用"自愿"接入；改不了 base_url 的进程、任意第三方程序完全逃逸在监控之外。

🧱

进程防火墙看不见

Portmaster / simplewall 只能按进程放行或阻断端口，看不到请求内容——密钥藏在 POST body 里，它们无能为力。

🐧

eBPF 上不了 Windows

eCapture 等 Hook SSL 函数的方案只支持 Linux；Windows 上没有成熟的内核态明文抓取路线。

🏢

企业 DLP 太重

面向千台终端的集中管控，部署重、无 AI 语义，也不理解"Agent 上传整个代码库"意味着什么。

👁️

已有的 MITM 工具只读

llm-interceptor 能看不能拦、靠手工配代理；CC-Monitor 可拦但不支持 Windows、只认单一工具。

🛡️

EgressSentinel 补上空白

任意进程 + 内容级审计 + 事中阻断的交集，目前没有现成方案同时满足——这就是本项目存在的原因。

核心能力

为什么选择 EgressSentinel？

一个代理，看清并管住本机所有进程的外发流量

🔍

HTTPS 明文级审计

基于 MIT 许可的 mitmproxy 引擎还原任意进程的完整请求/响应明文——URL、Header、Body 全部可查。

🎯

归因到进程

每条请求对应到发起进程的 PID、exe 路径、命令行与签名者；Node/Python/curl 客户端实测归因 100%。

⚖️

五维规则引擎

域名分类 / 进程画像 / 内容扫描 / 体量阈值 / 时间窗速率，YAML 策略热更新，支持 aaa policy lint 校验。

🔐

密钥与代码外泄检测

移植 gitleaks 43 条核心规则（AWS/GCP/Azure/OpenAI/私钥头/JWT…）+ PII 识别 + 代码密度/整库上传启发式。

🚦

四级响应，事中阻断

allow / alert / confirm / block。enforce 模式下违规请求被合成 403 拦截——目标服务器根本收不到；出厂默认 dry-run 只告警。

↩️

完整可逆，本地留痕

所有系统改动 journal-first 记录，aaa teardown 幂等还原（崩溃后仍完整还原）；证据仅存本机 SQLite，保留期可配。

🚀

安装即守护，全量监控

setup 完成即默认后台启动：五维规则与密钥/PII/代码三大扫描器开箱全开，开机自启——无需手动配置、无需重启。

🤖

常驻与自愈，杜绝断网

关机/注销 4 秒优雅收尾不阻塞系统；开机自启拉起代理；watchdog 检测「代理已启用但进程没跑」自动还原网络——没有 VPN 式开机断网问题。

开发者友好

四条命令，开始审计

下载单文件可执行（或 pip 源码安装），无需云端账号

先预览，后实施

aaa setup --dry-run 列出将做的全部系统改动；正式 setup 逐步确认并全部记录在案。

dry-run 出厂默认

只告警不阻断。观察无误后把策略改为 enforce，违规请求即刻被 403 拦截。

Node 系 Agent 也能抓

setup 自动下发 NODE_USE_ENV_PROXY / NODE_EXTRA_CA_CERTS 等变量——Node 默认不读系统代理和证书库，这一步是关键。

纯本地，零上传

事件库与证据文件只存本机目录，保留期自动清理；没有任何遥测或云端组件。

策略热更新，无需重启

编辑 policies/default.yaml 保存后约 2 秒自动生效（dry-run ↔ enforce 同理）；版本变化会写入运行日志，可随时确认当前生效版本。

quickstart.ps1
# ① 预览系统改动（推荐第一步）
aaa setup --dry-run
# ② 下发 CA / 代理 / 环境变量（逐步确认）
aaa setup
# ③ 启动审计代理（Ctrl+C 优雅退出）
aaa run
# ④ 打开本地面板 http://127.0.0.1:8787
aaa web
policies/default.yaml
version: 1
mode: dry-run   # 出厂默认只告警；确认规则后改 enforce
content:
  scanners: [secrets, pii, code_leak]
  rules:
    - { id: secret-leak, scanner: secrets, action: block }

常见问题

有疑问？我们来解答

EgressSentinel 是免费的吗？数据会上传到哪里？
MIT 协议开源、完全免费。纯本地运行：事件库与证据只写在本机 data/ 目录，保留期可配（aaa trim），没有任何遥测或云端组件。
它能审计哪些 AI 工具？算是 AI 审计 / agent 审计工具吗？
是的，EgressSentinel 就是面向本机的 AI 审计 / agent 审计工具：只要流量经过本机代理即可审计——Claude Code、Cursor、Codex、GitHub Copilot、Cline、Windsurf 等编程 Agent、MCP 服务，乃至任意联网程序都覆盖，不挑工具、无需接入 SDK。典型场景：审计 AI 编程工具是否私自上传代码 / .env / API key，做数据防泄密与代码防泄密。
为什么某个 AI Agent 的流量没被捕获？
Node.js 系工具（Claude Code、Cursor CLI 等）默认不读系统代理和 Windows 证书库。执行过 aaa setup env（注入 NODE_USE_ENV_PROXY / NODE_EXTRA_CA_CERTS 等）并重启该 Agent 进程即可；Python 系对应 REQUESTS_CA_BUNDLE。追求全覆盖可用需管理员的 local 模式（WinDivert 透明抓取）。
它会拖慢我的网络吗？
regular 模式是本地回环代理，无云端往返；内容扫描默认只处理每个请求的前 256KB，超大上传不会全文扫描；非审计目标域名跳过 body 扫描。
杀毒软件报警了怎么办？
本地代理 + 安装根证书对应 MITRE ATT&CK T1553.004，属预期行为，主流 EDR 可能有检测规则。regular 模式不加载任何驱动；本工具不隐藏自身行为，并提供完整卸载。请确认是你本人主动安装。
看到 CERTIFICATE_VERIFY_FAILED 是怎么回事？
目标进程尚未信任本工具的 CA——说明对应运行时的证书环境变量还没下发或进程没重启，按上一条处理；个别自带证书固定（pinning）的程序会持续失败，可加白名单降级为仅元数据审计。
突然关机后开机会「断网」吗？
不会。三层防护：关机/注销时代理 4 秒内优雅收尾（不阻塞系统关机）；开机计划任务自动拉起代理；若自启失败，登录 30 秒后 watchdog 检测到「代理已启用但端口不可达」会自动还原代理设置与相关环境变量（aaa watchdog --fix 也可手动触发），网络立刻恢复。
如何完全卸载？
一条命令：aaa teardown。按改动日志逆序幂等还原——删除 CA（按序列号精确匹配）、还原系统代理设置、清理全部环境变量；即使代理中途崩溃，重启后执行仍能完整还原，重复执行无副作用。
支持 Linux / macOS 吗？
v0.1.0 已发布五平台单文件可执行（Linux amd64/arm64、macOS amd64/arm64、Windows amd64）。Windows 是一等平台（归因、setup 下发完整可用）；Linux/macOS 的进程归因依赖特权会话，其余能力经 CI 矩阵回归，细节见仓库 docs/notes/decisions.md 缺口登记。
