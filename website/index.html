EgressSentinel（出口哨兵，原名 AI-AGENT-AUDIT） 是部署在 Windows 本机的 AI Agent 外发流量审计代理： 以 MITM 方式还原任意进程外发的 HTTP(S) 明文，把每条请求归因到进程， 按五维规则在事中阻断违规外发——全程本地留痕，不依赖应用自愿接入。

Problem

为什么需要它

AI Agent（Claude Code / Cursor / Codex 类 CLI、IDE 插件、MCP 后台服务……）在本机拥有读写代码的权限， 但它们外发 HTTPS 请求的内容对你是不可见的。是否存在私自上传代码、泄露密钥与 .env、 把敏感文件发给第三方端点——目前没有顺手的审计手段。

📦

整库代码上下文外发

Agent 把大段仓库源码作为上下文发给模型 API——超过 512KB 且代码相似度高的请求，正是要拦的形态。

🔑

密钥随 prompt 泄露

.env、AWS Key、GitHub Token 出现在请求体里。43 条密钥规则 + 熵检测在加密前所在的明文层命中它。

🕵️

陌生进程连 AI 端点

某个你没见过的后台进程正在访问 api.anthropic.com。进程画像规则会把"非 AI 进程访问 AI 端点"标记出来。

📈

异常频率的外联

60 秒内对同一域名发起 60+ 次请求的突发行为，由滑动时间窗规则捕获告警。

那现有方案为什么解决不了？——它们各自只补了一块拼图：

LLM 网关

需要应用"自愿"接入

LiteLLM / Helicone 等要求应用把 base_url 改指向网关。改不了 base_url 的进程完全逃逸——而失控的 Agent 恰恰不会配合。

进程防火墙

只有元数据，没有内容

Portmaster / simplewall 能告诉你"哪个进程连了哪个 IP:端口"并阻断连接，但看不到请求内容——密钥就在 body 里，它看不见。

eBPF 抓取

Windows 上不可用

eCapture 等在内核挂 SSL_write 取明文，但官方明言不支持 Windows（仅 Linux/Android）；ebpf-for-windows 至今没有 uprobe 能力。

企业端点 DLP

太重，且无 AI 语义

面向大企业管控台部署，成本与复杂度远超单机开发者；通用 DLP 也缺少 AI 端点画像与 Agent 进程理解。

最接近的 MITM 观测工具（如 llm-interceptor）也只读、不可阻断、靠手工配置代理，且只覆盖配置过的域名。 「Windows + 透明覆盖 + HTTPS 内容解析 + 事中阻断」这个交集，此前是空白——本项目即填补该空白。

如实说明：local 模式的代码路径与 WinDivert 依赖（mitmproxy-windows 0.12.15）已就绪， 非管理员会话下 CLI 会直接拒绝启动该模式（安全红线）；管理员环境下的实际抓取行为列入 docs/notes/local-mode-spike.md 的人工验证清单。engine 异常默认 fail-open（放行并记 error 事件），可配 fail-closed。

⚖️

MIT 许可的 mitmproxy

调研阶段核实了 LICENSE 原文：可作 Python 库嵌入并随本项目分发，无 GPL 传染顾虑。Portmaster / simplewall / mihomo 等 GPL 项目仅作架构范本，不引入代码。

🎯

进程归因是底线

regular 模式在连接建立瞬间用源端口反查系统连接表；local 模式由 WinDivert 在包层按 PID/进程名过滤。查不到的流量显式标记 unknown 并单独计数告警，绝不冒充归因成功。

🛑

事中阻断，不是事后报告

block 动作在 request 钩子内直接合成 403 响应，请求不会到达目标服务器；黑名单域名更早——在 SNI 阶段即断开，配合 lazy 连接策略做到零 TCP 触达。

🔁

完整卸载，可逆第一

所有系统改动（证书、代理、环境变量）先写入状态文件再实施（journal-first），aaa teardown 按记录逆序幂等还原——即使进程被强杀，重启后仍能完整还原。

Capabilities

核心能力：五维规则 × 密钥扫描 × 安全默认

每条请求经五个维度求值，命中规则按权重累加风险分（上限 100），动作取最高级： allow < alert < confirm < block。以下阈值为出厂策略 policies/default.yaml 的真实默认值。

01 domain 域名

端点分类与首连告警

  • known_ai_api：Anthropic / OpenAI / Gemini / DeepSeek / Moonshot / OpenRouter / xAI
  • code_hosting：github.com / api.github.com / gitlab.com
  • unknown 首连 → alert（按主机记忆，不重复噪音）
  • blocklist → SNI 阶段直接断开（enforce 下）
02 process 进程

进程画像与异常组合

  • agent_cli：claude / cursor / codex / copilot / node / python / java…
  • browser：chrome / msedge / firefox
  • 「非 AI 进程访问 AI 端点」→ alert（weight 30）
  • PID / exe 路径 / 命令行 / 公司信息随事件落库
03 content 内容

密钥 / PII / 代码外泄扫描

  • secrets：43 条规则（gitleaks 核心移植 + 熵 + allowlist），命中即 block
  • pii：邮箱 / 手机号 / 身份证 / 银行卡，命中 >10 处 → confirm
  • code_leak：本地绝对路径 / 代码密度 / multipart 上传 / 大块 base64
  • 全部纯正则+启发式，无网络调用，扫描截断 256KB
04 volume 体量

大体量外发识别

  • 单请求 >512KB 且代码相似度 >0.6 → confirm（疑似代码外发）
  • 单请求 >5MB → alert（huge-body）
  • 扫描截断上限 max_body_scan: 262144
05 time_window 时间窗

滑动窗口速率

  • 进程 × 域名 60 秒窗口内 >60 次请求 → alert（burst）
  • unknown 归因速率单独计数，归因质量可观测
06 verdict 判定

四级动作 + 风险分

  • allow 放行 · alert 告警留痕 · confirm 待人工决策 · block 事中拦截
  • risk_score = min(100, Σ weight)，仅供排序展示
  • confirm 决策：拒绝后同主机+同规则 TTL 内升级 block；允许仅一次性放行
🧪

dry-run 出厂默认

默认策略 mode: dry-run——只告警不阻断；切换 enforce 需显式修改策略文件。 策略支持 mtime 热更新（2 秒轮询），aaa policy lint 校验合法性。 引擎异常默认 fail-open 并记 error 事件，可配 fail-closed。

🙈

脱敏展示

命中的密钥在面板与事件中默认打码（⟦规则id|掩码片段⟧ 形态），打码与扫描共用同一匹配核心，永不漂移。 查看原文需显式 ?reveal=1 解锁，且解锁动作记入审计日志。面板仅监听本地回环。

🧾

证据留痕

每条事件落 SQLite（data/audit.db），请求 body 截断存为证据文件（默认上限 256KB）并记录 sha256； aaa report --verify-evidence 可复核证据完整性。保留期默认 14 天，可 aaa trim 清理。不上传任何数据。

Quick start

快速开始

以下命令与 src/aaa/cli.py 的实际实现一致（v0.1.0）。 环境：Windows 10/11，Python ≥ 3.11。

安装

在项目根目录以可编辑模式安装；需要本地面板时装上 web 扩展（fastapi + uvicorn）。

PowerShell / Git Bash
# 基础安装（采集引擎 + CLI）
pip install -e .

# 需要本地面板时（fastapi + uvicorn 为可选依赖）
pip install -e ".[web]"

# 确认安装
aaa --version   # aaa 0.1.0

一键 setup：CA 根证书 → 系统代理 → 用户环境变量

交互式向导，每一步先展示将要做的改动、确认后再实施；全部改动记录到 data/setup-state.json。

aaa setup
# 交互式一键引导（每步先展示改动再确认）
aaa setup

# 常用变体
aaa setup --dry-run          # 只预览动作，不实施任何系统改动
aaa setup --machine-ca       # CA 装到 LocalMachine（需管理员；默认 CurrentUser 静默导入）
aaa setup --yes              # 跳过逐步确认（自动化用）

# 也可分步执行
aaa setup ca --store user    # user | machine
aaa setup proxy              # WinINET 用户代理 127.0.0.1:8080（--winhttp 加机器级，需管理员）
aaa setup env                # 下发 HTTP(S)_PROXY / NODE_* / REQUESTS_CA_BUNDLE 等环境变量

运行审计代理

默认 regular 模式、监听 127.0.0.1:8080，事件落 SQLite，启动时按保留期（默认 14 天）自动清理。

aaa run
# 默认 regular 模式（系统代理），Ctrl+C 优雅退出
aaa run

# local 模式：WinDivert 透明抓取，需「管理员」终端；可限定目标进程
aaa run --mode local
aaa run --mode local --pid 12345
aaa run --mode local --process claude

# 其他常用选项
aaa run --port 8080 --policy policies/default.yaml
aaa run --jsonl              # 额外镜像写 data/raw/YYYYMMDD.jsonl（默认仅 SQLite）
aaa run --retention-days 7   # 调整保留期

观察：CLI 与本地面板

状态总览、实时事件流、聚合报告、Web 面板（仅本地回环）。

aaa status / tail / report / web
# 当前状态：代理 / CA / 策略版本 / 事件数 / 最近 5 条事件 / 待还原改动
aaa status

# 实时滚动新事件（rich Live；可按判定/进程/主机过滤）
aaa tail --verdict block

# 聚合报告：按判定 / 进程 / 主机 / 规则统计
aaa report --since 24h
aaa report --since 7d --csv          # 或 --json
aaa report --verify-evidence         # 复核全部证据文件 sha256

# 本地面板（需先安装 .[web]）：过滤 → 查看（脱敏）→ 解锁 → 导出 → confirm 决策
aaa web                               # http://127.0.0.1:8787，仅本地回环

# 校验 / 清理
aaa policy lint                       # pydantic 严格校验策略文件
aaa trim --days 14                    # 清理过期事件与证据

完整还原（卸载）

按状态文件逆序、幂等还原全部改动；崩溃/强杀后重跑同样有效。

aaa teardown
# 还原全部：CA 证书、系统代理、用户环境变量
aaa teardown

# 限定范围（可多选）
aaa teardown ca proxy env

aaa teardown --dry-run       # 先看看会还原什么

关于阻断：出厂默认 mode: dry-run（只告警不阻断）。 要启用事中阻断，编辑 policies/default.yaml 将 mode 改为 enforce（保存即热更新，无需重启）。 关于 aaa harden on|off（防火墙防绕过加固）：该命令目前为 P6 占位，仅打印规划说明，不会对系统做任何改动。

Roadmap

路线图（P6 强化项）

v1 主体（采集 / 归因 / 规则引擎 / 存储 / CLI / Web 面板）已实现； 以下为执行计划 docs/03-execution-plan.md 中 P6 阶段的强化项，按需排期。

防绕过加固未实施 · CLI 占位

aaa harden on：防火墙仅放行本工具的 443/TCP 出站、拒绝其他进程 443/TCP、 并拒绝 UDP 443 逼 QUIC 回落可审计的 TLS（Zscaler 等商用方案的标准做法）。 内置 svchost / Windows Update 白名单，启用前 dry-run 列出受影响进程，规则进状态文件可还原。 当前 aaa harden 为占位命令，任何参数都不触碰防火墙。

LLM 辅助判定规划中

仅对规则引擎判 alert / confirm 的事件触发：截断+脱敏后的摘要送 OpenAI 兼容接口， 返回结构化结论（is_violation / reason / category）。硬性约束：每事件 token 上限、每日成本上限、可整体关闭， 判定结果只作参考、不直接 block。

服务化常驻规划中

NSSM / 计划任务安装为系统服务（自动重启、日志），托盘 UI 与核心服务分进程、经本地 IPC 通信 （规避 Session 0 隔离）。部分落地 基于 PyInstaller 的单文件 exe 打包已构建并通过冒烟验证（命令与代理转发均正常）。

另有 T6.4 响应侧增强在列：prompt-injection 特征标记（promptfoo 攻击语料反向用作检测特征）与 ETW 归因增强。

Compliance

合规与使用边界

抓取本机 HTTPS 明文属于高权限监控行为。本工具的立场是：能力透明、边界明示、随时可逆。

仅用于授权设备

只用于审计自己拥有或被明确授权管理的计算机。部署到他人设备前必须获得授权——这不是道德建议，而是使用前提。

安装根证书的风险提示

信任自建 CA 等价于 MITRE ATT&CK T1553.004（Subvert Trust Controls）， 可能触发杀软 / EDR 告警；WinDivert 驱动同样可能被个别 AV 拦截。 本工具不隐藏自身行为：安装动作全部显式确认、先打印将执行的改动再实施、支持 --dry-run 预览。

数据留在本机

事件与证据只写本地 SQLite / 证据目录，不联网上传任何数据；UI 默认脱敏展示，命中的密钥打码、解锁需显式操作并留审计日志； 保留期默认 14 天，随时可 aaa trim 清理。

完整卸载

aaa teardown 依据 journal-first 状态文件，逆序、幂等地还原 CA 证书（按序列号精确删除，不误删）、 系统代理与全部下发过的环境变量；即使进程被强杀，重启后重跑仍能完整还原——不留残留。
