# 07 · 版本发布检查单（Release Checklist）

> 规则来源：用户要求（2026-10-25）——**每次版本更新都必须同步维护官网介绍**。
> 适用范围：任何打 tag 发布的新版本（v0.x.y）。发布负责人在打 tag 前逐项核对。

## 必查项

1. **CHANGELOG**：本版段落已写入 `CHANGELOG.md`（新增/变更/修复三段式，中文）。
2. **官网版本徽标**（`website/index.html`）：hero 的 `vX.Y.Z 正式发布`（zh）与 `vX.Y.Z released`（en）同步为本版号；统计带数字（测试数等）按实际更新。
3. **官网能力介绍**：本版新增的用户可感知能力必须反映到官网——
   - 重要能力 → 「核心能力」卡片区新增卡片（中英双语 + `feat.cNt/cNp` 词条）；
   - 中等能力 → 「快速开始/特性列表」条目或 FAQ；
   - 状态变化 → 「路线图」区状态板（✅ 已落地 vX.Y.Z / 🚧 进行中 / ⏳ 待命）。
4. **官网与实现一致性**：新增 CLI 命令若出现在官网文案中，须与 `src/aaa/cli.py` 实际命令一致（文案忠于实现红线）。
5. **英文词条**：所有新增 `data-i18n` 节点必须在 `I18N_EN` 字典中有对应词条（发布前浏览器切 EN 全页扫一遍，零中文残留）。
6. **JSON-LD/OG**：若版本号出现在结构化数据或 og 文案中，一并更新。
7. **vibe.html**：里程碑级版本（x.0）更新其数字（版本数/测试数）。
8. **本地验证**：`http.server` 起官网 → 浏览器过一遍（默认浅色/暗色切换/中英切换/截图抽查）再推送；Pages 自动部署后抓取线上确认。
9. **Release 正文**：由 CI 自动从 CHANGELOG 提取（`scripts/release_notes.py`），无需手写——但打 tag 后应核对该段确实出现。
10. **三线全绿**：CI / Build / Pages 全部 success 后才算发布完成。

## 责任分工

- 官网维护（本检查单 2-8）：发布负责人（当前为 GLM-5.3）执行，不派给实现工作流。
- CHANGELOG/版本号/文档：由集成分支的任务合同要求实现方完成。
